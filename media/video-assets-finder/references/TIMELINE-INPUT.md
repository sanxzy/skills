# Timeline interpretation (self-contained)

Read the entire `<title_name>.timeline.md`, not a prefix. Typical sections: `## Metadata`, `## Editorial Direction`, `## Visual Sequences`, `## Audio Timeline`, `## Transition Map`, `## Editorial Validation`; optional Narrative Beat Index. No separate skill is needed to understand this format.

- `### VIS-SEQ-003 | HH:MM:SS.mmm–HH:MM:SS.mmm` is an editorial **picture region**, not an asset, shot, narrative beat, or final cut. Its `Visual: VIS-003 — ...` text describes the actual visual requirement. One sequence may contain several `VIS-` IDs, staged internal states, overlays, or a continued base picture. Keep IDs distinct and reference sequence(s) for timing; when a paragraph has no explicit VIS ID, assign a stable host-only synthetic requirement ID (`REQ-VIS-<sequence>-<ordinal>`) without modifying the source. Preserve original text and origin.
- `Source Cues: 5–13` references narration SRT cue numbers, not a start/end point in the source media being sought. Source-relative `relevantRange` is discovered separately. The timeline's interval is presentation need; do not pretend that interval is a timestamp in a YouTube video.
- `HOLD VIS-003` means reuse/continue that visual, not seek a duplicate asset. A true `NONE` creates no external asset. A `PRIMARY_FOOTAGE` with a user-supplied local path can be checked and registered; absent primary footage is not proof that a source exists. Require the user-provided material or report missing/conditional rather than searching for a falsely interchangeable replacement.
- A visual like an accurate person, event, period, or named place is factually constrained even when its prose has no machine-readable `Specificity:` field. Extract *only* explicitly supported constraints. `EXACT`, `ENTITY_SPECIFIC`, `LOCATION_SPECIFIC` are hard gates; `REPRESENTATIVE` accepts appropriately labeled illustrative footage; conceptual graphics generally stay with editing. Never turn a constraint into a weaker one or treat title metadata alone as visual confirmation.
- `## Audio Timeline` owns `SRC-AUD-###`, `MUS-###`, `AMB-###`, `SFX-###` when present. A source-audio line may link a visual requirement: preserve same-source relationship (including `NAT_SOUND`); a video file can physically satisfy both IDs without splitting audio. A short `Audio:` note in a visual sequence referring to a `MUS`/`AMB`/`SRC-AUD` ID is **not** a new requirement. `SOURCE_AUDIO — None specified`, `SFX — No forced ...`, and `MUSIC OFF` create no search task. Do not assume source audio exists because an illustrative visual is requested.
- Music/ambience marked `optional` or `may enter` still merit a search if the description identifies a meaningful target; retain optional status. If a condition depends on unavailable primary footage, preserve the condition and search only what can be honestly specified. `GRAPHIC`, `DIAGRAM`, `MAP`, `CHART`, `TEXT`, `MOTION_GRAPHIC`, `GENERATED_VISUAL` that must be made during editing are checklist/manifest `WILL_BE_MADE_DURING_EDITING`, except when explicitly requested as existing external material. An explicitly sourced still may be acquired as `mediaKind: IMAGE` and probed for dimensions; for an explicitly continuous moving-footage need set manifest `requiresMotion: true` and do not claim a still covers that duration.
- Several visual elements under one `VIS` may require more than one source only if the timeline's observable distinct content or requested multiplicity demands it. Group their findings under the one requirement ID and map each asset/range. Conversely, a shared source may satisfy multiple requirement IDs. No artificial one-asset-per-BEAT or one-asset-per-cue rule.

Before dispatch, write a compact per-ID extraction record in `progress.todo.md`: original intent (quote/faithful summary), type, optionality, source sequence/times, duration if stated, specificity/hard constraints, audio relationship, present status and next action. The host checks the complete timeline twice: first for visual and audio IDs, second for unnumbered requirements, repeats, HOLD, and non-search work. If ambiguity materially changes selection, ask the user; otherwise record uncertainty and do not invent a fact.
