# Audio Script

Turn a numbered `.srt` narration timeline (including one generated by `video-script`) into an Eleven v3 performance script. **Preserve the original narration's meaning, factual scope, attribution, language, order, and uncertainty.** This is voice direction, not a second research or scriptwriting pass. Read only the narration file; do not require or consult its `.source.md` companion. Do not call ElevenLabs or claim to have listened to generated audio. This skill is standalone: the format, direction guidance, example, and splitter live in this directory; no other skill or external documentation is needed at runtime. Study the hand-directed [island opening](examples/real-directed-walkthrough.md), [full Giethoorn everyday-life story](examples/giethoorn-directed-walkthrough.md), [full Rockefeller case](examples/crime-directed-walkthrough.md), and [full Miyako investigation](examples/miyako-directed-walkthrough.md) for voice craft; [standalone-workflow.md](examples/standalone-workflow.md) shows the bare input/output format.

## Input and deliverables

Input: `.artifacts/video-scripts/<stem>.srt`, or a user-supplied standard SRT file with consecutive cue numbers and one or two text lines per `HH:MM:SS,mmm --> HH:MM:SS,mmm` cue. Each cue contains one short spoken thought across one or two visual subtitle lines, except `♪ ♪` placement cues. The helper joins an SRT visual line break as a space in the working-draft narration; it never treats the second subtitle line as another source block. Accept a supplied path; never infer content from a filename. The helper converts each SRT time range into a non-spoken `[MM:SS.mmm–MM:SS.mmm]` working-draft anchor (minutes may exceed 59). Do not use `<stem>.source.md`, `<stem>.voice.md`, or `<stem>.voice.map.md` as input narration. Bundled older `.md` examples are pending manual SRT migration and are not the new input contract.

Write **two files beside the input timeline**, keeping the same stem:

- `<stem>.voice.md` — numbered segments, each with a fenced `text` block containing *only* Eleven v3 input. Headings/fences are for human copying; never paste them into ElevenLabs. No source timecodes, speaker labels, production directions, metadata, citations, or invented narration inside the fenced text.
- `<stem>.voice.map.md` — the original source path, segment-to-block/timecode correspondence, warnings about likely timing overruns, and a record of changes to spoken wording. Editorial timecodes are not measured audio timings.

Do not overwrite or alter the input timeline. An intermediate working draft may exist during processing; it is not a third deliverable. For revisions, regenerate the two outputs together from the revised draft, not one at a time.

## Non-negotiable: direct the voice manually

**The agent must author and edit the performance by hand for the entire narration.** Read each passage for meaning, then deliberately choose its phrasing, information focus, stress-bearing word, processing pause, and delivery shift. Shape the pre-focus → focus → landing across sentences, not just the mood at the top of a block. Leave routine sentences untagged when their wording already carries the delivery. Preserve the source's spoken meaning and uncertainty.

**Never programmatically compose the directed draft.** Do not use a script, bulk search-and-replace, mechanical tag insertion, a fixed tag-per-block template, or copied raw narration with a single `[calm]`/`[serious]` prefix as a substitute for voice direction. Shorter segments alone do not create nuance: the phrasing and local cues must be thoughtfully written **before** the splitter runs. Code may parse anchors, validate coverage, count characters, and divide **already hand-directed** passages; it must not decide emphasis, punctuation, pauses, tags, contour, or emotional transitions. The test fixture's plain-text draft is for structural tests only, never a model of finished direction.

**Quality gate:** inspect every resulting segment, especially its opening and last thought. If it is a dense untouched source paragraph, or an entire multi-idea passage has only one generic mood cue, return to the working draft and manually score its intonation units; do not merely lower the character limit or add tags uniformly. Compare with the [hand-directed example](examples/real-directed-walkthrough.md). A passing splitter test confirms structure, **not** voice quality.

## Workflow

1. **Read the entire source timeline.** Identify its language, existing tone, factual qualifiers, narrative turns, silence/visual gaps, and any `♪ ♪` music blocks. Preserve all spoken blocks, in order. `♪ ♪` is a video-track music/SFX placement marker, never spoken narration or a v3 sound-effect prompt. Omit it entirely from `.voice.md` and record its source interval in the map for video-track placement. Do not fill visual gaps with invented speech.
2. **Choose the performance.** Follow the user's explicit delivery brief and the script's own tone; otherwise use restrained documentary. Read [style-recipes.md](references/style-recipes.md) for four reusable recipes and the format for custom styles. Voice choice and Stability belong to the eventual ElevenLabs operator, not to the pasted text; do not invent a voice ID or guarantee that a style tag exists.
3. **Direct the whole script before segmenting.** Author one complete working draft with every source anchor on its **own line**, followed by the directed text for that block. Separate blocks with a blank line. For example:

   ```text
   [00:00.000–00:08.000]
   [calm] Di pagi itu, jalan masih sepi.

   [00:10.000–00:18.000]
   Namun, satu keputusan mengubah semuanya.
   ```

   Preserve the source anchor exactly for every block, including video-track `♪ ♪` markers if present (leave those markers unchanged in the working draft so the helper can map and exclude them). An inline SRT abbreviation such as `[Mr.]` or `[Jend.]` is **spoken text**, not an Eleven v3 Audio Tag: manually write `Mr.` or `Jend.` without square brackets in the directed draft so the title is spoken rather than interpreted as a tag. The helper rejects bracketed abbreviations in drafts; leave legitimate v3 direction tags unchanged. **Manually score each meaningful beat before running the helper**: identify pre-focus/setup → one information nucleus (the stress-bearing word) → post-focus/payoff, decide whether the phrase holds or lands, then break long source blocks into short intonation passages using blank lines. Keep contour arrows and planning labels outside the TTS text. Tags that stand alone (for example `[short pause]` or `[thoughtful]`) attach to the following spoken passage when split. Place emphasis on the single word that changes the information; use pauses and local shifts to make the argument audible rather than prefixing one tag to an entire long block. Write every passage by hand, in source order. Do not manually divide the draft into final numbered segments. If a change of topic/delivery makes a particularly good segment boundary, put `<!-- beat -->` on its own line **between** source blocks; the helper removes it from output. Mark only meaningful turns, not every block.
4. **Apply minimal Eleven v3 direction.** Read the bundled [ElevenLabs recipes and tag catalog](references/elevenlabs-recipes.md) and [v3-direction.md](references/v3-direction.md). The catalog covers documented examples, experimental cues, a precision-delivery decision guide for timing/tempo/emphasis, and sound tags excluded from this narration skill; it is a broad reference, not a closed or guaranteed v3 enum. Work from information focus and sentence phrasing to punctuation, then add a documented tag only where needed. Keep tags close to their target passage. Prefer a natural spoken rhythm over repeated ellipses, all-caps, or a tag on every sentence. Do not add unsupported dramatic implications to uncertain statements. Retain quoted wording and attribution; expand numbers, dates, units, acronyms, or names only for a clearer spoken reading without changing the claim. Do not add fabricated dialogue, reactions, sound effects, or claims. Use the narration's language for spoken text; documented tags may remain in English. No SSML `<break>` for Eleven v3.
5. **Run the bundled splitter** after the full draft is written:

   ```bash
   python3 <skill-dir>/scripts/build_voice.py .artifacts/video-scripts/<stem>.srt <working-draft-path>
   ```

   The Python standard-library helper verifies that draft anchors match the source one-for-one, splits **the manually written intonation passages within each timecoded block** into short copy-ready segments, strips anchors and beat markers, and writes both output files. It never invents phrasing, focus, or direction. It reports possible timing overruns and spoken-word differences. If outputs already exist, use `--force` only after inspecting them. Do not bypass a failed check by silently dropping a block or cutting words. Run `python3 <skill-dir>/scripts/build_voice.py --help` for `--target-chars` and `--max-chars` options. Never exceed the v3 5,000-character documented request limit; the helper's default cap is lower for headroom. If a directed passage is too long, split it manually at a meaningful spoken phrase or sentence boundary within the **same** source anchor and retry; do not truncate speech, invent sub-block timestamps, or silently change source timecodes.
6. **Audit both outputs.** Compare each final fenced segment against the draft. Verify that every source narration block is present in order, all `♪ ♪` placement blocks are absent from `.voice.md` and accounted for in the map, all changes listed in the map are safe spoken-form adjustments, and segment starts/ends are natural. If the helper's automatic cut harms continuity, add or move a `<!-- beat -->` hint in the working draft and rerun; adjust direction at the boundary if necessary. Check likely overrun warnings by reading the marked passages aloud or estimating in the output language. If timing is tight, flag it instead of removing supported facts. Do not claim that tags, punctuation, or original timecodes guarantee recorded timing.
7. **Deliver** links to both files and mention any important timing or pronunciation issues. Delete the working draft only after successful verification if it was created as a disposable temporary file. No API calls, audio, waveform, or exact delivery promises.


## Production limits

Eleven v3 direction is voice- and generation-dependent. The same input can sound different on another take. Voice selection and Stability (Creative, Natural, Robust) affect response; Natural is a reasonable audition starting point, not a mandatory setting. A separate numeric v3 Speed control is inconsistently described in the reviewed product material, so do not assume it works. Pause tags are qualitative, not exact durations. Request Stitching is not available for `eleven_v3`; segments have no guaranteed cross-request prosody. The map is for editorial alignment after generation, not an automated timing guarantee. Listen and edit in downstream production when actual audio exists.
